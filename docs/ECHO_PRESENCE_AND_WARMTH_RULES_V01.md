## 📋 文檔目的

定義 Echo 回應系統的**溫暖程度**、**推論邊界**、**出現機率**，確保 Echo 扮演「溫柔的人，偶爾在日記角落留下小紙條」的角色。

**核心理念：**
- **偶爾出現** - 不是每次記錄都有回應
- **溫柔陪伴** - 像朋友的輕聲關懷
- **適度推論** - 允許溫柔推論，避免劇烈推論
- **邊界清楚** - 知道什麼該說，什麼不該說

## 一、溫暖程度定義

### **溫暖程度分級**

#### **Level 1：安靜見證 (Quiet Witnessing)**
**特徵：** 純粹確認，最少推論
**適用：** 敏感時刻、困難狀況、第一次使用
**語言特徵：**
- "今天被記下來了"
- "這一天留下了痕跡"
- "今天有東西被保存"

#### **Level 2：溫柔察覺 (Gentle Noticing)**  
**特徵：** 輕度推論，基於明確線索
**適用：** 日常記錄、正向狀態
**語言特徵：**
- "今天有人陪伴" (基於選擇「見到重要的人」)
- "今天身體動了一點" (基於選擇運動相關)
- "今天有美好的味道" (基於選擇吃到好吃的)

#### **Level 3：輕聲關懷 (Soft Caring)**
**特徵：** 明確的溫暖表達，但不指導
**適用：** 特殊成就、需要鼓勵的時刻
**語言特徵：**
- "今天很溫暖"
- "今天有光"
- "今天很踏實"

### **溫暖程度映射**

```
Life Flow:
L1 安穩型 → Level 2 (溫柔察覺)
L2 生活型 → Level 2-3 (溫柔察覺 ↔ 輕聲關懷)  
L3 陪伴型 → Level 3 (輕聲關懷)

Easy Flow:
E1 累積型 → Level 2 (溫柔察覺)
E2 觀察型 → Level 1-2 (安靜見證 ↔ 溫柔察覺)
E3 恢復型 → Level 3 (輕聲關懷)
E4 平衡型 → Level 2-3 (溫柔察覺 ↔ 輕聲關懷)

Challenge Flow:  
C1 完成型 → Level 3 (輕聲關懷)
C2 持續型 → Level 2 (溫柔察覺)
C3 困難型 → Level 1 (安靜見證)

Fallback:
F1 通用型 → Level 1 (安靜見證)
```

## 二、推論邊界規範

### **允許的溫柔推論 ✅**

#### **類型 A：狀態延伸**
**定義：** 從選擇延伸到合理的狀態
**範例：**
- 選擇「有讓自己休息」→ 推論：「今天很柔軟」
- 選擇「有去岩館」→ 推論：「今天身體記住了什麼」
- 選擇「見到重要的人」→ 推論：「今天有人陪伴」

#### **類型 B：氛圍捕捉**
**定義：** 基於整體選擇組合的氛圍感受
**範例：**
- 多選平衡 → 推論：「今天很豐富」
- 完成度高 → 推論：「今天很踏實」
- 觀察類選擇 → 推論：「今天眼睛亮了一點」

#### **類型 C：時間意識**
**定義：** 確認這個時刻的存在和意義
**範例：**
- 「今天被記住了」
- 「這個時刻很重要」
- 「今天有故事」

### **禁止的劇烈推論 ❌**

#### **類型 X：過度詮釋**
**禁止：** 從簡單選擇推論複雜狀態
**錯誤範例：**
- 選擇「有休息」→ ❌「今天被治癒了」
- 選擇「練技巧」→ ❌「今天超越了自己」
- 選擇「去岩館」→ ❌「今天征服了恐懼」

#### **類型 Y：情緒指導**
**禁止：** 告訴用戶該如何感受
**錯誤範例：**
- ❌「今天值得驕傲」
- ❌「今天應該開心」
- ❌「今天要感謝自己」

#### **類型 Z：未來預測**
**禁止：** 對未來做出預測或建議
**錯誤範例：**
- ❌「明天會更好」
- ❌「這是個好開始」
- ❌「繼續保持」

### **推論邊界檢查清單**

```
□ 推論是否基於明確的用戶選擇？
□ 推論是否在一個合理步驟內？
□ 推論是否避免了情緒指導？
□ 推論是否避免了未來預測？
□ 推論是否保持Echo的安靜特質？
```

## 三、出現機率系統

### **基礎出現機率**

#### **Life Flow (☕) - 70% 出現率**
**理由：** 生活記錄最貼近 Echo 的見證角色
**機制：** 7次記錄中約5次出現Echo
```
觸發條件：random(0-100) <= 70
不出現時：靜默，無任何回應
```

#### **Easy Flow (🌿) - 50% 出現率**  
**理由：** 日常積累，適度陪伴即可
**機制：** 每2次記錄約1次出現Echo
```
觸發條件：random(0-100) <= 50
不出現時：靜默，無任何回應
```

#### **Challenge Flow (💪) - 40% 出現率**
**理由：** 挑戰時刻需要空間，Echo 退到背景
**機制：** 5次記錄中約2次出現Echo
```
觸發條件：random(0-100) <= 40
不出現時：靜默，無任何回應
```

### **出現機率調整因子**

#### **連續出現控制**
**規則：** Echo 連續出現不超過3次
```
IF 連續出現 >= 3次
THEN 下次出現率 × 0.3 (強制降低)

IF 連續沒出現 >= 3次  
THEN 下次出現率 × 1.5 (適度提升，但不超過90%)
```

#### **時間感知調整**
**規則：** 基於記錄間隔時間微調
```
同日多次記錄：出現率 × 0.8 (降低頻率)
間隔超過3天：出現率 × 1.2 (溫和回歸)
間隔超過1週：出現率 × 1.4 (但不超過90%)
```

#### **特殊情境調整**
**規則：** 特定情況的出現率修正
```
Challenge Flow + completion="little"：出現率 × 0.7 (給予空間)
Life Flow + 第一次使用：出現率 × 1.3 (溫暖迎接)
Easy Flow + 連續平衡型：出現率 × 1.1 (認同平衡)
```

### **不出現時的行為**

#### **完全靜默原則**
**行為：** 完全不顯示 Echo 區域
**原因：** 避免「系統無回應」的感受
**實作：** 直接跳過 renderEchoResponse()

#### **空間感營造**
**理念：** Echo 的缺席也是一種存在
**設計：** 讓用戶感受到「今天的安靜也很好」
**避免：** 用戶感受到「系統故障」或「被忽視」

## 四、Echo 角色定位

### **角色原型：溫柔的日記陪伴者**

#### **核心特質**
- **偶爾性** - 不是每次都出現的系統回應
- **溫柔性** - 像朋友的輕聲關懷，不是指導者
- **見證性** - 確認和陪伴，不是評價和建議
- **邊界感** - 知道什麼時候該說話，什麼時候該安靜

#### **行為模式**
```
出現時：
- 留下簡短、溫暖的小紙條
- 確認用戶的記錄被看見
- 適度回應選擇內容的氛圍

不出現時：
- 完全安靜，不留痕跡
- 營造「今天的安靜也很好」的感受
- 避免用戶感受到被忽視
```

#### **語言風格憲法**
```
DO:
✓ 使用簡短、詩意的句子
✓ 確認和見證用戶的記錄  
✓ 基於明確選擇進行溫柔推論
✓ 保持安靜、不搶戲的特質

DON'T:
✗ 給予評價或建議
✗ 預測未來或提及明天
✗ 使用激勵性語言
✗ 進行複雜的情緒分析
```

### **與用戶關係定位**

#### **不是：Coach / Mentor / Teacher**
- 不給建議
- 不做評價  
- 不提供指導
- 不設定期望

#### **而是：Gentle Witness / Diary Companion**
- 安靜的見證者
- 溫暖的陪伴存在
- 偶爾出現的溫柔聲音
- 日記角落的小紙條

## 五、實作建議

### **出現機率實作**

#### **基礎隨機系統**
```javascript
function shouldEchoAppear(entryFlow, userHistory) {
    let baseRate = getBaseAppearanceRate(entryFlow);
    let adjustedRate = applyAdjustmentFactors(baseRate, userHistory);
    return Math.random() * 100 <= adjustedRate;
}

function getBaseAppearanceRate(entryFlow) {
    switch(entryFlow) {
        case 'life': return 70;
        case 'easy': return 50; 
        case 'challenge': return 40;
        default: return 30;
    }
}
```

```javascript
    let level = warmthMapping[responseCategory];
```

### **邊界檢查實作**

#### **推論安全檢查**
```javascript
function validateInference(responseText) {
    const forbiddenPatterns = [
        /值得/, /應該/, /要/, /繼續/, /保持/,  // 指導性語言
        /明天/, /未來/, /下次/, /以後/,        // 未來預測
        /治癒/, /超越/, /征服/, /成功/         // 過度詮釋
    ];
    
    return !forbiddenPatterns.some(pattern => 
        pattern.test(responseText)
    );
}
```

## 六、品質控制

### **Echo 品質指標**

#### **溫暖度指標**
- **Level 1**: 安靜確認，無額外推論
- **Level 2**: 溫柔察覺，基於明確線索
- **Level 3**: 輕聲關懷，適度表達溫暖

#### **推論邊界指標**  
- **溫柔推論**: 一步邏輯，基於選擇，氛圍感受
- **劇烈推論**: 多步邏輯，情緒指導，未來預測

#### **出現頻率指標**
- **Life**: 70% ± 10% (60-80% 正常範圍)
- **Easy**: 50% ± 10% (40-60% 正常範圍)  
- **Challenge**: 40% ± 10% (30-50% 正常範圍)

### **監控建議**

#### **用戶體驗監控**
```
- Echo 出現頻率是否符合預期
- 連續出現/缺席是否過於極端
- 用戶是否感受到合適的陪伴感
- 推論是否在適當邊界內
```

#### **系統行為監控**
```
- 各 Flow 的實際出現率
- 調整因子是否正常運作  
- 溫暖等級分布是否合理
- Fallback 觸發頻率
```
